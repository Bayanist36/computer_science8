# Урок 15. Алгоритмическая конструкция «следование». Линейный алгоритм

## 1\. Главное о теме

Любой алгоритм собирается из трёх конструкций, и самая простая из них — следование: команды выполняются одна за другой, каждая ровно один раз. Научимся строить такие алгоритмы, записывать их схемой и программой и проверять работу трассировочной таблицей.

Дальше разберём по шагам: три конструкции, из которых строится всё; что такое линейный алгоритм; блок-схема линейного алгоритма; программа линейного алгоритма; трассировочная таблица.

## 2\. Три конструкции, из которых строится всё

В 1960-х годах программисты спорили, можно ли обойтись без сложных конструкций вроде безусловного перехода. Ответ оказался положительным: любую программу удаётся собрать из трёх простых элементов. Их называют базовыми алгоритмическими конструкциями, и в школьном курсе они идут именно в этом порядке — от простого к сложному.

Следование — единственная конструкция, которая не требует ни проверки условий, ни повторений. Исполнитель получает список команд и выполняет их сверху вниз, ровно по одной. Именно поэтому следование изучают первым: в нём нет ничего, кроме порядка.

Ветвление и цикл появятся на следующих уроках, но уже сейчас важно понять главное: любая сложная программа — это комбинация трёх элементов. Умение видеть в задаче последовательность, выбор и повторение и есть алгоритмическое мышление.

| Конструкция | Что делает | Ключевое слово |
|:---|:---|:---|
| Следование | Команды выполняются по порядку | нет |
| Ветвление | Выбор одной из ветвей по условию | если |
| Цикл | Повторение группы команд | пока, для |

## 3\. Что такое линейный алгоритм

> **Определение.** Линейный алгоритм — алгоритм, в котором команды выполняются последовательно одна за другой в порядке записи и каждая ровно один раз.

Алгоритм, построенный только из следования, называется линейным. Его признаки легко проверить: в записи нет условий, нет повторений, каждая команда выполняется ровно один раз, а количество шагов известно ещё до начала работы.

Линейными являются многие вычислительные задачи: найти значение выражения по формуле, перевести единицы измерения, посчитать стоимость покупки, определить периметр фигуры. Во всех этих случаях набор действий не зависит от того, какие числа подставлены, — меняются только значения, но не порядок работы.

| Задача | Линейный алгоритм | Почему |
|:---|:---|:---|
| Перевести рубли в копейки | да | одно вычисление, порядок неизменен |
| Найти большее из двух чисел | нет | нужен выбор одной из двух ветвей |
| Посчитать стоимость покупки | да | цена умножается на количество |
| Вывести цифры числа по одной | нет | нужно повторять действие |

> «Линейный» не значит «короткий» или «простой». Линейный алгоритм может содержать двадцать шагов, и всё равно останется линейным — лишь бы в нём не было условий и повторов.

## 4\. Блок-схема линейного алгоритма

Блок-схема линейного алгоритма выглядит как вертикальная цепочка: овал «Начало», затем блоки ввода, вычислений и вывода, в конце — овал «Конец». Между каждыми двумя соседними блоками ровно одна стрелка, и идёт она сверху вниз. Никаких разветвлений и возвратов назад в такой схеме нет.

По схеме удобно проверять порядок работы. Если вы видите, что стрелка возвращается вверх, — перед вами цикл. Если из блока выходят две стрелки с подписями «да» и «нет» — перед вами ветвление. Для линейного алгоритма характерна единственная дорога от начала к концу.

> Типичная ошибка: нарисовать на схеме ввод и вывод одним прямоугольником. По ГОСТ 19.701-90 ввод и вывод обозначаются параллелограммом, а прямоугольник предназначен только для вычислений.

```text
    ( Начало )
         |
    / ввод a, b /
         |
   [ S := a * b ]
         |
    / вывод S /
         |
    ( Конец )
```

## 5\. Программа линейного алгоритма

> **Определение.** Присваивание — команда, которая вычисляет значение выражения справа и записывает его в переменную, указанную слева.

В программе линейный алгоритм записывается как последовательность операторов. Компьютер выполняет их сверху вниз, поэтому порядок строк — это и есть порядок работы. Переменная — это именованная ячейка памяти: запись `S = a * b` означает «вычислить произведение и положить результат в ячейку с именем S».

Присваивание не является уравнением из математики. Запись `x = x + 1` не означает «x равен x плюс один» — она означает «взять текущее значение x, прибавить единицу и записать обратно». Поэтому такие операторы выполняются по очереди, и результат зависит от того, что было в ячейке раньше.

Особый случай — обмен значений двух переменных. Если написать `a = b`, а потом `b = a`, оба имени будут указывать на одно и то же значение: первое число потеряется безвозвратно. Чтобы поменять значения местами, нужна третья, временная переменная.

> Имена переменных в Python чувствительны к регистру: `Sum`, `sum` и `SUM` — три разные переменные. Ошибка в регистре не выдаёт сообщения, программа просто работает не так, как задумано.

```python
a = int(input("Сторона a: "))
b = int(input("Сторона b: "))
P = 2 * (a + b)
print("Периметр:", P)
```

```python
c = a
a = b
b = c
```

## 6\. Трассировочная таблица

> **Определение.** Трассировочная таблица — таблица, в которой по шагам записывают значения переменных после выполнения каждой команды алгоритма.

Проверить алгоритм «на глаз» трудно, особенно если в нём пять-шесть команд. Надёжный способ — **трассировка**: выполнить алгоритм вручную и записать в таблицу, как менялись значения переменных после каждого шага.

Столбцы таблицы — это переменные, строки — шаги. В первой строке фиксируют исходные данные, затем после каждой команды переписывают значения всех переменных, даже если они не изменились. Так видно, на каком именно шаге значение получилось неожиданным — и где искать ошибку.

| Шаг | Команда | a | b | c |
|:---|:---|:---|:---|:---|
| 0 | исходные данные | 3 | 4 | — |
| 1 | c := a + b | 3 | 4 | 7 |
| 2 | c := c * c | 3 | 4 | 49 |

> Прочерк в ячейке означает, что переменная ещё не получила значения. Если программа попытается прочитать такую переменную, исполнитель остановится с ошибкой — это называется обращением к неопределённой переменной.

## 7\. Разобранные примеры

### Пример 1. Трассировка по блок-схеме

**Условие.** Дана блок-схема: Начало → ввод a, b → c := a + b → d := c · c → вывод d → Конец. Найдите результат при a = 3, b = 4 и заполните трассировочную таблицу.

**Решение.** Заводим столбцы для переменных a, b, c, d. Исходные данные: a = 3, b = 4, остальные значения не определены. Шаг 1: c := a + b = 3 + 4 = 7. Шаг 2: d := c · c = 7 · 7 = 49. Шаг 3: вывод d показывает 49.

**Ответ:** d = 49.

### Пример 2. Обмен значений двух переменных

**Условие.** В переменных a и b хранятся числа 5 и 8. Нужно поменять их местами. Ученик записал алгоритм: a := b; b := a. Что получится и как исправить алгоритм?

**Решение.** После первой команды a := b значение a стало равно 8, а прежнее значение 5 потеряно — его нигде не сохранили. Вторая команда b := a присваивает b текущее значение a, то есть снова 8. В итоге обе переменные равны 8, обмена не произошло.

Правильный алгоритм использует временную переменную c: c := a (теперь 5 сохранено), a := b (a = 8), b := c (b = 5). Проверим трассировкой.

**Ответ:** при записи без третьей переменной обе переменные станут равны 8; правильный обмен — через c, результат a = 8, b = 5.

### Пример 3. Линейный алгоритм с делением нацело

**Условие.** Перевести 3725 секунд в часы, минуты и секунды, используя только линейные команды (без циклов и условий).

**Решение.** В одном часе 3600 секунд, в одной минуте 60. Сначала выделяем целые часы: h := s div 3600. Затем берём остаток и выделяем из него минуты: ost := s mod 3600, m := ost div 60. Остаток от деления на 60 — это секунды: sec := ost mod 60.

Подставляем s = 3725: h = 3725 div 3600 = 1; ost = 3725 mod 3600 = 125; m = 125 div 60 = 2; sec = 125 mod 60 = 5. Проверка: 1 · 3600 + 2 · 60 + 5 = 3600 + 120 + 5 = 3725 — сходится.

**Ответ:** 1 ч 2 мин 5 с.
