### 3\. Изучение нового материала (20 мин)

**Учитель:** Алгоритм — это функция: каждому входу соответствует ровно один выход. Значит, результат можно получить без запуска программы — пройти по шагам, записать значения в таблицу и прочитать последнюю строку.

#### 3\.1. Результат как следствие входных данных (~4 мин)

<note type="quote">
  Анализ алгоритма — исследование его работы без запуска: определение результата при заданных входных данных и выяснение того, какие результаты возможны вообще.
</note>

**Учитель:** У детерминированного алгоритма нет свободы выбора: при одном и том же входе и одной и той же среде он всегда даёт один и тот же результат. Это свойство превращает алгоритм в функцию — правило, которое каждому допустимому входу ставит в соответствие выход. Именно поэтому результат можно вычислить карандашом на бумаге: никакой скрытой случайности в изученных конструкциях нет.

**Учитель:** Различайте два вопроса, которые звучат похоже. Первый: «что выведет программа при n = 42?» — здесь ответ единственный, и его даёт трассировка. Второй: «какие значения вообще может вывести эта программа?» — здесь ответом служит множество, и его получают перебором классов входов: по ветвям, по чётности, по количеству цифр. Второй вопрос сложнее, но именно он проверяет, понимаете ли вы алгоритм, а не умеете ли считать.

**Учитель:** Обратное утверждение неверно: одинаковый результат могут дать разные входы. Программа, печатающая остаток от деления на 3, выдаст 1 и для 4, и для 7, и для 100. Поэтому «возможные результаты» — это множество выходов, а не список входов; сколько входов приходится на каждый выход, мы разберём на следующем уроке.

<note type="quote">
  Детерминированность не означает предсказуемость «на глаз». Программа из пяти строк с двумя переменными и циклом может дать результат, который интуиция не угадывает: именно поэтому нужна таблица, а не прикидка.
</note>

#### 3\.2. Таблица трассировки: как её вести (~4 мин)

<note type="quote">
  Таблица трассировки — таблица, в которой каждая строка фиксирует значения переменных после очередного шага алгоритма.
</note>

**Учитель:** Трассировка — это запись исполнения. Порядок работы такой: сначала выписываем переменные и их начальные значения, затем выполняем команды строго по порядку и после каждой записываем новое состояние. Строка таблицы соответствует одному шагу, столбец — одной переменной. Если переменная на этом шаге не менялась, её значение просто переносится в новую строку.

**Учитель:** Для цикла удобнее считать шагом не строку кода, а одну итерацию: тогда видно, сколько раз тело выполнилось и на каком значении условие стало ложным. Для ветвления полезно добавить столбец «какая ветвь выбрана»: это защищает от ошибки, когда ученик выполняет обе ветви подряд.

**Учитель:** Разберём этот фрагмент. Начальные значения: n = 4, s = 1. Цикл перебирает i от 1 до 4. После i = 1: s = 1. После i = 2: s = 2. После i = 3: s = 6. После i = 4: s = 24. Цикл закончился, на экран выводится 24 — это факториал числа 4.

| Шаг | i | s после шага | Проверка условия |
|:---|:---|:---|:---|
| начало | — | 1 | — |
| 1 | 1 | 1 | 1 в диапазоне |
| 2 | 2 | 2 | 2 в диапазоне |
| 3 | 3 | 6 | 3 в диапазоне |
| 4 | 4 | 24 | 4 в диапазоне |
| конец | 5 | 24 | 5 вне диапазона |

<note type="quote">
  Типичная ошибка — начинать накопитель с нуля там, где идёт умножение. С s = 0 произведение всегда останется нулём. Для суммы начальное значение 0, для произведения — 1.
</note>

```python
n = 4
s = 1
for i in range(1, n + 1):
    s = s * i
print(s)                # 24
```

#### 3\.3. Ветвление: разбор по ветвям (~4 мин)

**Учитель:** При трассировке ветвления главное — не выполнять лишнего. Проверка идёт сверху вниз: как только условие оказалось истинным, выполняется его блок, а все остальные ветви пропускаются целиком, вместе с их условиями. Поэтому порядок ветвей меняет результат: строгое условие должно стоять выше общего.

**Учитель:** Проверим три входа. Для x = −5 первое условие истинно: y = 5, остальные ветви не проверяются. Для x = 3 первое условие ложно, второе истинно: y = 6. Для x = 10 первое ложно (10 не меньше 0), второе ложно (10 не меньше 10), значит, работает else: y = 11. Особый случай — x = 0: он не меньше нуля, поэтому попадает во вторую ветвь и даёт y = 0.

| Вход x | Первое условие | Второе условие | Ветвь | Результат y |
|:---|:---|:---|:---|:---|
| −5 | истинно | не проверяется | первая | 5 |
| 0 | ложно | истинно | вторая | 0 |
| 3 | ложно | истинно | вторая | 6 |
| 10 | ложно | ложно | else | 11 |

<note type="quote">
  Ошибка на границе — самая частая в заданиях с ветвлением. Сравнение x < 10 и x <= 10 дают разные наборы входов: во втором случае число 10 попадает во вторую ветвь и результат меняется с 11 на 20.
</note>

```python
x = int(input())
if x < 0:
    y = -x
elif x < 10:
    y = x * 2
else:
    y = x + 1
print(y)
```

#### 3\.4. Циклы: число повторений и накопители (~4 мин)

**Учитель:** Цикл — единственная конструкция, где число шагов зависит от данных. Для while оно заранее неизвестно и определяется тем, как быстро меняется переменная условия. Ускорение или замедление этого изменения меняет результат целиком: если делить на 3 вместо 2, итераций станет меньше, а итоговое значение другим.

**Учитель:** Проследим: 200 → 100 (k = 1) → 50 (2) → 25 (3) → 12 (4) → 6 (5) → 3 (6) → 1 (7). Теперь условие 1 > 1 ложно, цикл закончен, выводится «1 7». Обратите внимание на шаг 25 → 12: деление нацело отбрасывает остаток, поэтому последовательность не совпадает с точным делением пополам.

| Итерация | n до тела | n после тела | k |
|:---|:---|:---|:---|
| 1 | 200 | 100 | 1 |
| 2 | 100 | 50 | 2 |
| 3 | 50 | 25 | 3 |
| 4 | 25 | 12 | 4 |
| 5 | 12 | 6 | 5 |
| 6 | 6 | 3 | 6 |
| 7 | 3 | 1 | 7 |

<note type="quote">
  Последняя проверка условия в таблицу значений не входит: когда n = 1, тело уже не выполняется, и k остаётся равным 7, а не 8. Именно на этом шаге чаще всего ошибаются при подсчёте итераций.
</note>

```python
n = 200
k = 0
while n > 1:
    n = n // 2
    k = k + 1
print(n, k)
```

#### 3\.5. Возможные результаты: перебор вариантов (~4 мин)

**Учитель:** Чтобы найти все возможные результаты, не нужно перебирать все числа. Достаточно разбить входы на классы, внутри которых программа ведёт себя одинаково: по выбранной ветви, по чётности, по числу цифр. Каждый класс даёт один результат или короткую формулу, и множество результатов складывается из них.

**Учитель:** Для x от 1 до 3 работает первая ветвь: получаются 2, 4, 6. Для x от 4 до 6 работает вторая: получаются 1, 2, 3. Объединяем: возможные результаты — 1, 2, 3, 4, 6. Значение 5 не получается ни при одном входе, хотя лежит внутри диапазона. Это и есть ответ на вопрос «может ли программа вывести 5» — не может.

<note type="quote">
  Вопрос «какие результаты возможны» проверяют обратным ходом: берут подозрительное значение и смотрят, есть ли вход, который его даёт. Отсутствие такого входа нужно доказать разбором всех ветвей, а не фразой «не получилось».
</note>

```python
x = int(input())        # 1 <= x <= 6
if x <= 3:
    y = x * 2
else:
    y = x - 3
print(y)
```

## Приложение: опорный конспект для доски

```
АНАЛИЗ АЛГОРИТМА: ВОЗМОЖНЫЕ РЕЗУЛЬТАТЫ

ВХОД  --->  АЛГОРИТМ  --->  ВЫХОД
один вход - ровно один выход (детерминированность)

ТРАССИРОВКА
  столбцы: переменные | строки: шаги
  ветвление: отметить выбранную ветвь
  цикл: строка = одна итерация
  последняя строка - значения перед выводом

ВЕТВЛЕНИЕ
  проверка сверху вниз, работает ПЕРВАЯ истинная ветвь
  x < 0  |  x < 10  |  else        (граница решает всё)

ЦИКЛ
  условие проверяется ДО тела
  while: шагов столько, сколько нужно до ложного условия
  200 -> 100 -> 50 -> 25 -> 12 -> 6 -> 3 -> 1     k = 7

МНОЖЕСТВО РЕЗУЛЬТАТОВ
  разбить входы на классы (ветви, чётность, разрядность)
  собрать выходы классов, проверить каждый подстановкой
  не все значения диапазона достижимы
```
