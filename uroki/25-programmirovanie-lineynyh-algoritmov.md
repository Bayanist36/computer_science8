### 3\. Изучение нового материала (20 мин)

**Учитель:** Линейная программа выполняется сверху вниз, без пропусков и повторов, поэтому вся её логика — в правильной записи выражений. Один неверный приоритет операции или лишний знак деления превращает верный алгоритм в неверный ответ.

#### 3\.1. Линейный алгоритм (~4 мин)

<note type="quote">
  Линейный алгоритм — алгоритм, в котором все команды выполняются последовательно, в порядке записи, и каждая ровно один раз.
</note>

**Учитель:** **Линейным** называют алгоритм, в котором команды выполняются последовательно, в порядке записи, и каждая ровно один раз. В нём нет условий и повторений: программа не выбирает путь и не возвращается назад. Именно такие алгоритмы решают большинство расчётных задач — от пересчёта валюты до вычисления площади.

**Учитель:** На блок-схеме линейный алгоритм выглядит как вертикальная цепочка: овал «начало», затем прямоугольники действий и параллелограммы ввода-вывода, в конце овал «конец». Стрелка всегда одна и идёт вниз — ветвлений нет. Такая схема читается сверху вниз, как и сама программа.

**Учитель:** По линейному принципу устроены и бытовые инструкции: «достань ключ, вставь в замок, поверни два раза, открой дверь». Если переставить шаги, результат изменится. В программе так же: порядок строк — часть алгоритма, а не оформление.

#### 3\.2. Арифметические выражения и приоритет операций (~4 мин)

<note type="quote">
  Арифметическое выражение — запись из чисел, переменных и знаков арифметических операций, значение которой вычисляется по правилам приоритета.
</note>

**Учитель:** Выражение в программе записывается в одну строку, без дробной черты и без «двухэтажных» формул. Поэтому важно, где поставить скобки. Знаки операций в Python те же, что в математике, плюс три особых: `//` — целочисленное деление, `%` — остаток, `**` — возведение в степень.

**Учитель:** Порядок действий определяется приоритетом. Сначала выполняется возведение в степень, затем умножение, деление, целочисленное деление и остаток (они равноправны и выполняются слева направо), в последнюю очередь — сложение и вычитание. Скобки отменяют этот порядок: всё, что внутри, вычисляется первым.

**Учитель:** В первой строке: `4 ** 2 = 16`, затем `3 * 16 = 48`, затем `48 // 8 = 6`, затем `2 + 6 − 1 = 7`. В третьей строке видно, что унарный минус слабее степени: `-2 ** 2` равно −4, а `(-2) ** 2` равно 4. Степень выполняется справа налево, поэтому `2 ** 3 ** 2` — это `2 ** 9 = 512`, а не `8 ** 2`.

| Операция | Знак | Пример | Результат |
|:---|:---|:---|:---|
| сложение | + | 7 + 2 | 9 |
| вычитание | − | 7 − 2 | 5 |
| умножение | * | 7 * 2 | 14 |
| деление | / | 7 / 2 | 3.5 |
| целочисленное деление | // | 7 // 2 | 3 |
| остаток | % | 7 % 2 | 1 |
| степень | ** | 7 ** 2 | 49 |

<note type="quote">
  Знак `^` в Python не возводит в степень, а выполняет другую операцию: `2 ^ 3` даёт 1, а не 8. Для степени используется только `**`, поэтому запись `x ^ 2` — типичная ошибка переноса из математики.
</note>

```python
print(2 + 3 * 4 ** 2 // 8 - 1)
print((2 + 3) * 4)
print(-2 ** 2, (-2) ** 2)
print(2 ** 3 ** 2)
```

#### 3\.3. Целочисленное деление и остаток (~4 мин)

**Учитель:** Обычное деление `/` в Python всегда даёт вещественное число: `8 / 2` равно `4.0`, а не `4`. Если нужна только целая часть, применяют `//`: `7 // 2 = 3`. Остаток от деления даёт `%`: `7 % 2 = 1`. Эти две операции всегда работают в паре и связаны равенством `a = (a // b) * b + a % b`.

**Учитель:** Целочисленное деление и остаток незаменимы, когда целое нужно разложить на части. Секунды раскладываются на часы, минуты и секунды; конфеты — на полные пакеты и остаток; число — на чётность (остаток от деления на 2). Во всех случаях важен именно целый результат, а не дробь.

**Учитель:** Первая строка даёт число полных часов: `3725 // 3600 = 1`. Вторая — число полных минут в остатке: `3725 % 3600 = 125`, затем `125 // 60 = 2`. Третья — оставшиеся секунды: `3725 % 60 = 5`. Вместе: 1 час 2 минуты 5 секунд.

<note type="quote">
  Для отрицательных чисел Python округляет вниз, а не к нулю: `-7 // 2 = -4`, `-7 % 2 = 1`. В школьных задачах мы работаем с неотрицательными числами, где результат совпадает с привычным делением с остатком.
</note>

```python
sec = 3725
print(sec // 3600)
print(sec % 3600 // 60)
print(sec % 60)
```

#### 3\.4. Тип результата и округление (~4 мин)

**Учитель:** Тип результата зависит от операции: `+`, `−`, `*` над целыми дают целое, а `/` — всегда `float`. Поэтому `10 / 2` на экране выглядит как `5.0`. Если нужен целый вид, применяют преобразование `int(...)`, но оно именно **отбрасывает** дробную часть: `int(3.9) = 3`, `int(-3.9) = -3`.

**Учитель:** Для настоящего округления есть функция `round`. С одним аргументом она округляет до целого, со вторым — до указанного числа знаков после запятой: `round(3.14159, 2) = 3.14`. При ровно половине Python округляет к чётному: `round(2.5) = 2`, `round(3.5) = 4`.

**Учитель:** Последняя строка показывает особенность вещественных чисел: `0.1 + 0.2` даёт `0.30000000000000004`. Причина в том, что в двоичной памяти дробь хранится приближённо. Для школьных задач это не мешает, но результат сравнения дробей и вывода денежных сумм требует округления: `round(0.1 + 0.2, 2)` вернёт `0.3`.

<note type="quote">
  `int(2.99)` равно 2, а не 3. Если требуется округление, а не отбрасывание, используйте `round`, иначе ошибка в ответе появится незаметно.
</note>

```python
print(10 / 2, int(10 / 2))
print(7 / 2, round(7 / 2))
print(round(2.5), round(3.5))
print(0.1 + 0.2)
```

#### 3\.5. Типичные ошибки в записи выражений (~4 мин)

**Учитель:** Первая группа ошибок — потерянный знак умножения. В математике `2x` означает «два умножить на x», в Python такая запись вызовет синтаксическую ошибку: между числом и переменной нужен `*`. Вторая группа — неверный приоритет: среднее арифметическое `(a + b) / 2` без скобок превращается в `a + b / 2`, и при `a = 5`, `b = 4` вместо 4.5 получается 7.

**Учитель:** Третья группа связана с типами: там, где ожидается дробный ответ, случайно применённое `//` даёт целое и молча теряет остаток. Четвёртая — деление на ноль: оно останавливает программу с ошибкой `ZeroDivisionError`, и никакого «бесконечно большого числа» не появляется.

| Ошибка | Как записано | Как правильно |
|:---|:---|:---|
| нет знака умножения | 2x | 2 * x |
| степень через ^ | x ^ 2 | x ** 2 |
| потеряны скобки | a + b / 2 | (a + b) / 2 |
| целое вместо дроби | 7 // 2 | 7 / 2 |
| деление на ноль | 10 / 0 | проверить делитель |

<note type="quote">
  Проверяйте формулу на простых числах, где ответ считается устно. Если выражение верно для 2 и 3, оно, скорее всего, верно и для больших значений; если расходится — ошибка в скобках или в знаке операции.
</note>

## Приложение: опорный конспект для доски

```
ЛИНЕЙНЫЙ АЛГОРИТМ: команда 1 -> ... -> команда N
  каждая выполняется ровно один раз

ОПЕРАЦИИ:  +  -  *   / (float)   // (целое)   % (остаток)   ** (степень)
ПРИОРИТЕТ: 1) **   2) * / // %   3) + -   4) скобки
СВЯЗЬ:  a = (a // b) * b + a % b
  17 // 5 = 3    17 % 5 = 2    17 / 5 = 3.4

ТИПЫ:  int(3.9) = 3   round(3.5) = 4   round(2.5) = 2
  10 / 2 = 5.0   (деление всегда float)

ОШИБКИ: 2x -> 2 * x    x^2 -> x ** 2
  a + b / 2 -> (a + b) / 2
  10 / 0 -> ZeroDivisionError
```
